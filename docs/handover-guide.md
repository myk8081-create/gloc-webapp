# GLOC 재고관리 웹앱 최종 인수인계 가이드

이 문서는 고객에게 최종 납품할 때 확인해야 할 항목을 한 번에 정리한 체크리스트입니다.
납품 대상은 웹앱 소스코드, Google Sheets 데이터, Apps Script API, Vercel 배포, Figma 디자인입니다.

## 1. 고객에게 전달할 항목

| 항목 | 전달 내용 | 비고 |
| --- | --- | --- |
| 운영 사이트 | Vercel 배포 URL 또는 고객 도메인 | QR과 카카오톡 링크에 사용 |
| GitHub 저장소 | `https://github.com/myk8081-create/gloc-webapp.git` | 고객에게 관리자 권한 또는 소유권 이전 |
| Google Sheets | 대리점관리, 재고현황, 발주현황, 제품등록, settings 시트 | 고객 Google 계정 소유 권장 |
| Apps Script | `apps-script/Code.js`가 들어간 웹 앱 API | 고객 계정에서 재배포 권장 |
| Figma 디자인 | `https://www.figma.com/design/Rqw30EQ6XyLG4hH5UMfbJg` | 디자인 수정용 |
| 관리자 계정 | 관리자 ID, 초기 비밀번호, 대리점 코드 `ADMIN` | 비밀번호는 별도 안전 채널로 전달 |
| 대리점 안내문 | 공통 접속 링크, 초기 ID/PW, 대리점 코드 | 웹앱의 QR/안내문 화면에서 생성 |

## 2. 납품 전 최종 점검

- `npm run build`가 오류 없이 통과해야 합니다.
- Vercel 환경변수가 운영 값으로 들어가 있어야 합니다.
- 운영 사이트에서 샘플 모드가 아니라 실제 Google Sheets 데이터로 로그인되어야 합니다.
- 관리자 로그인 후 본사 재고, 전체 대리점/샵 재고, 제품등록, 대리점 계정관리, 발주관리가 열려야 합니다.
- 대리점 로그인 후 내 재고 수정, 본사 재고 조회, 전체 대리점/샵 재고 조회, 발주신청이 동작해야 합니다.
- QR 또는 카카오톡 링크로 모바일 접속 시 로그인 화면이 바로 열려야 합니다.
- 고객이 관리자 비밀번호를 변경했는지 확인해야 합니다.

## 3. Google Sheets 소유권 이전

권장 방식은 고객 Google 계정이 최종 소유자가 되는 것입니다.

1. 고객 Google 계정으로 새 스프레드시트를 만들거나 기존 제작용 스프레드시트의 소유권을 고객에게 이전합니다.
2. 시트 이름과 컬럼이 아래 구조와 같은지 확인합니다.
3. 고객 Google 계정에서 `확장 프로그램 > Apps Script`를 엽니다.
4. 저장소의 `apps-script/Code.js` 내용을 Apps Script 편집기에 붙여 넣습니다.
5. `setupInitialData` 함수를 1회 실행해서 기본 시트와 관리자 계정을 생성합니다.
6. 고객 계정으로 Apps Script 웹 앱을 새로 배포합니다.

필수 시트:

- `대리점관리`
- `재고현황`
- `발주현황`
- `제품등록`
- `settings`

## 4. Apps Script 웹 앱 재배포

1. Apps Script에서 `배포 > 새 배포`를 누릅니다.
2. 유형은 `웹 앱`을 선택합니다.
3. 실행 계정은 `나`로 설정합니다.
4. 액세스 권한은 운영 정책에 맞게 설정합니다.
5. 배포 후 발급되는 `/exec` URL을 복사합니다.
6. Vercel 환경변수 `APPS_SCRIPT_API_URL`에 이 URL을 넣습니다.

프론트엔드에는 Google Sheets 원본 URL을 넣지 않습니다. 웹앱은 Apps Script Web App URL만 호출합니다.

## 5. Vercel 환경변수

Vercel 프로젝트의 `Settings > Environment Variables`에서 아래 값을 운영 기준으로 등록합니다.

```text
DATA_MODE=appsScript
APPS_SCRIPT_API_URL=https://script.google.com/macros/s/고객_배포_ID/exec
APP_PUBLIC_URL=https://고객_운영_도메인
```

환경변수를 바꾼 뒤에는 반드시 다시 배포해야 사이트에 적용됩니다.

## 6. GitHub 인수인계

고객이 직접 유지보수할 예정이면 아래 중 하나로 처리합니다.

- 고객 GitHub 계정을 저장소 collaborator로 추가하고 관리자 권한을 부여합니다.
- 고객 조직 또는 고객 계정으로 저장소 소유권을 이전합니다.
- 고객이 원하면 ZIP 파일로 소스코드를 별도 전달합니다.

Vercel이 GitHub 저장소와 연결되어 있으면 `main` 브랜치에 push될 때 자동 배포됩니다.

## 7. Figma 디자인 인수인계

디자인 파일:

```text
https://www.figma.com/design/Rqw30EQ6XyLG4hH5UMfbJg
```

고객이 디자인을 직접 수정해야 하면 Figma 파일 권한을 `Can edit`로 공유합니다.
Figma에서 디자인을 바꾼 것만으로 실제 웹앱은 자동 변경되지 않습니다.
디자인 변경 후에는 변경된 화면명과 수정 내용을 기준으로 프론트엔드 코드에 다시 반영해야 합니다.

## 8. 운영자 계정 전달

초기 관리자 계정은 고객에게 별도 안전 채널로 전달합니다.

```text
아이디: admin
대리점 코드: ADMIN
초기 비밀번호: setupInitialData 실행 시 생성된 초기 비밀번호
```

고객에게 전달 후 바로 관리자 비밀번호를 변경하도록 안내하세요.
대리점 계정의 초기 비밀번호는 해시로만 저장되므로 나중에 다시 확인할 수 없습니다.
초기 비밀번호를 잊었거나 다시 안내해야 할 때는 관리자 화면에서 `PW 초기화`를 한 뒤 새 비밀번호를 전달합니다.

## 9. QR과 카카오톡 링크 전달

현재 구조는 대리점별 QR이 아니라 공통 QR/공통 링크를 사용합니다.
대리점 구분은 로그인 아이디, 비밀번호, 대리점 코드로 처리합니다.

운영 링크 예시:

```text
https://고객_운영_도메인/login
```

고객은 관리자 화면의 QR/안내문 메뉴에서 공통 QR을 다운로드하고, 대리점별 초기 ID/PW/대리점 코드가 포함된 카카오톡 안내문을 복사해 전달하면 됩니다.

## 10. 고객에게 안내할 운영 규칙

- 제품 추가/수정/삭제는 관리자 계정에서 진행합니다.
- 본사 재고는 관리자 계정에서 수정합니다.
- 대리점/샵 재고는 각 대리점/샵 계정에서 직접 수정합니다.
- 관리자는 전체 대리점/샵 재고를 조회할 수 있습니다.
- 대리점/샵은 본사 재고와 전체 대리점/샵 재고를 조회할 수 있지만, 수정은 본인 재고만 가능합니다.
- 발주 상태 변경은 관리자만 가능합니다.
- 계정을 삭제하면 해당 대리점의 재고 행도 삭제되고, 기존 발주 이력은 보존됩니다.

## 11. 최종 납품 순서

1. 로컬에서 `npm run build`로 빌드 확인
2. 최신 코드를 GitHub `main` 브랜치에 push
3. Vercel 배포 완료 확인
4. 고객 Google 계정으로 Sheets/Apps Script 이전 또는 재생성
5. 고객 Apps Script Web App URL을 Vercel 환경변수에 적용
6. Vercel 재배포
7. 운영 사이트에서 관리자/대리점 로그인 테스트
8. QR 모바일 접속 테스트
9. 고객에게 GitHub, Vercel, Google Sheets, Apps Script, Figma 권한 전달
10. 고객이 관리자 비밀번호를 변경했는지 확인

```text
안녕하세요.

운영 사이트:
https://고객_운영_도메인/login

관리자 로그인:

대리점 코드: ADMIN

관리자 로그인 후 반드시 비밀번호를 먼저 변경해 주세요.
대리점 계정 생성, 제품 등록, 본사 재고 수정, 발주 상태 변경은 관리자 화면에서 가능합니다.

대리점에는 관리자 화면의 QR/카카오톡 안내문 메뉴에서 생성한 공통 링크와 초기 로그인 정보를 전달하면 됩니다.
```
